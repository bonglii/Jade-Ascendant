## Source-verified facts and explicit boundary

- `SaveManager.SAVE_DOMAINS` contains EIGHT permanent schema-v1 domains: `achievements`, `daily_quests`, `equipment`, `idle_cultivation`, `inventory`, `journey`, `pavilion`, `progression`. The NINTH `checkpoint` is active-run and device-only. The CI tests read **the actual source registry** and fail if a domain, scope, required field or schema version drifts.
- `scripts/managers/cloud_save_snapshot_contract.gd` and `cloud_save_snapshot_capture.gd` deliberately remain the existing **SIX-domain local preview**. They continue excluding Pavilion and Idle Cultivation. Gate 6 does not replace the live client preview or make that incomplete payload transferable. There is NO implicit migration or cloud sync.
- Pavilion contains Celestial Jade, Seals, summon pity, one-time claims, purchase-related local flags and at most 1,024 locally stored processed grant IDs. **Critical source finding:** `PavilionManager.apply_verified_iap_purchase` constructs `"iap:" + product_id + ":" + purchase_token`, placing a RAW Google Play purchase token in `processed_grant_ids`. The Gate 6 structural preview now FAILS CLOSED when it sees an `iap:` grant marker; do not silently upload this field, strip evidence, or reuse local grant history as a server-ledger. A deliberate privacy-safe migration with global server dedup is required. Idle Cultivation has last-claim/last-observed client timestamps, capped local rewarded grant IDs and cross-domain reward dependencies. Merely copying these fields does **not** prove balances, earned rewards, time, ledger ownership or purchase validity.
- Equipment/Inventory structural consistency can be partially verified (counts for equipped items, duplicate slots, ascension references); catalog semantics and server economy remain unresolved. Gate 6 does not assert whole-account economic reconciliation.

## Isolated implementation

1. `src/snapshot/full_permanent_draft_v2.mjs` is a **pure draft-format v2 structural inspector**, intentionally separate from the v1 Godot preview: exact eight domains, exact v1 schema map and registry-required keys, Pavilion and Idle field allowlists, common numeric/list/JSON bounds, no active-run field, inventory/equipment structural checks, capped payload. Invalid, forged, incomplete and cross-account fixtures fail closed. Drafts containing `iap:` grant IDs carrying raw purchase tokens are rejected before any future serialization/transport. Every inspection result always reports `economy_verified=false`, `server_revision_verified=false`, `upload_allowed=false`, `restore_allowed=false`. Client `owner_uid`, `captured_at_unix` and any SHA-256 digest are not server authority.
2. `src/snapshot/firestore_gate6_emulator_model.mjs` models **test-only server revision allocation and atomic eight-domain snapshot history** using the already reviewed Firebase Admin SDK with hard `JADE_GATE5_EMULATOR_ONLY=1`, exact demo project and localhost Firestore emulator guard. Its in-memory opaque `WeakMap` synthetic proof is minted only after structural checking, inside the isolated QA process. That marker is **not real reconciliation** and is never accepted through the deployed callable. A transaction checks simulated authenticated owner, revision CAS, reconciliation hold, overflow and duplicate unchanged state, then atomically creates a fresh immutable `qa_snapshots/rev_x` and advances the simulated account revision.
3. Separate QA collections (`gate6_qa_accounts_v1/...`) avoid altering Gate 5's synthetic global purchase-ledger transaction collections. Gate 5 code and all paid reward handling remain unchanged; **cross-model atomic economy reconciliation is not implemented or asserted**.
4. `gate6_full_permanent_draft.test.mjs` reads actual SaveManager/Pavilion/Idle/old-client-preview source, checks field drift and tests malicious/corrupt/missing/replay/incomplete payloads. `gate6_firestore_emulator.test.mjs` uses synthetic accounts to test exact eight-domain snapshot CAS, owner isolation, forged-proofs, stale race, concurrent contenders, reconciliation hold, immutable prior revisions, and duplicate-unchanged snapshots.
5. Existing `.github/workflows/cloud-economy-gate5-qa.yml` runs new Gate 6 syntax/unit tests and both Gate 5 + Gate 6 emulator transaction suites in the **same** pinned, isolated demo-only Firestore Emulator run. No additional Firebase project, credentials, service account or network write to production. Existing Godot and Auth/Functions QA must remain green on the same SHA.

## High-impact STOP conditions before Gate 7/8 or paid Economy production

- Production cannot mint `syntheticProof`: it must reconcile eight permanent domains against **trusted server ledger events, purchase validation, offline rewards and ownership**, rather than trust an Android-provided `server_reconciled` flag, content hash, client clock or local `processed_grant_ids`. A refactoring that exposes this test-only model as a callable is a security regression.
- All remote mutations must be authorized from Firebase verified Auth UID + validated App Check, run under reviewed IAM, use real transaction atomicity and a global token dedupe; Google Play purchases must be verified through Developer API and refunds/revocations handled. Gate 5's ledger emulator currently tracks **only one synthetic Celestial Jade account field** and is not transaction-closed with the eight-domain snapshot model.
- Account deletion, legacy purchases lacking trusted account binding, item catalog validation, format migration, physical device clock drift, save size, backup/rollback, conflict UX, offline accumulation and crash recovery remain pending. A successful demo CAS does not make restoring the full account safe.
- A Firestore document has a size cap; this QA deliberately restricts the preview to 512 KiB, not a production storage architecture or canonical cross-language serialization guarantee. Client SHA-256 protects integrity diagnostics only, not economic authenticity.
- Firestore Admin SDK bypasses Firestore Security Rules. Current test-only deny-all rules never authorize a client; production needs separate review of service IAM and published Firestore Rules. See https://firebase.google.com/docs/firestore/security/test-rules-emulator.
- `backend/cloud_save/functions/index.mjs` must **still export exactly one read-only callable** (`jadeCloudSaveCapabilities`). `backend/cloud_save/predeploy_gate.json` must stay `PRE_DEPLOYMENT_ONLY`. Do not deploy anything on Firebase Spark, auto-enable cloud writes/restores, merge to main or stage unrelated local project files.
