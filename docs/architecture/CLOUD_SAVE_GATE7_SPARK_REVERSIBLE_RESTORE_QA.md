This patch neither deploys Firebase nor touches Godot gameplay, UI, player files, monetization, permissions, Firestore production data or Auth configurations. `main` remains isolated.

## Why the gate is necessary

`SaveManager` has EIGHT permanent domains (achievements, daily_quests, equipment, idle_cultivation, inventory, journey, pavilion, progression) and a ninth active-run `checkpoint`, plus a real disk journal/backup. The existing live Cloud Save capture still deliberately covers only SIX domains and never authorizes transfer; Gate 6's eight-domain model is synthetic and disconnected from game code. Gate 5's ledger and Gate 6's snapshot use **separate emulator account collections**; their transitions are not yet an indivisible economic commit. None of these provides a real migration/restore, secure purchase or cross-device solution.

The local Pavilion domain may contain **raw Google Play purchase tokens** in `processed_grant_ids` (`iap:...`). The Gate 6 v2 inspector rejects all such drafts. No attempt is made to send, rewrite or strip existing purchase history: that requires a reviewed privacy-safe migration and a server deduplication ledger. Client clocks, unkeyed SHA-256 digests and the symbolic Gate 6 reconciliation proof are **not** authoritative. Local active runs and equipment loadout snapshots stay device-only. Undoing an older server snapshot without reconciling an earned reward, purchase or refund would be unsafe.

## Exactly what this patch adds

- `src/restore/reversible_restore_sandbox.mjs`: pure **in-memory** device simulator that refuses implicit consent, offline mode, active runs, checkpoints, pending journals, identity switches, unvalidated local/remote eight-domain drafts and stale server revision/digest. A successful synthetic restore stages exactly eight domains, retains an ephemeral copy of the old state until explicit account-bound confirmation, and allows manual rollback. Ten injected failures (0–8 staged domains or immediately after promotion) restore the complete original state. It rejects a second restore while the backup is pending; test-only concurrent local changes invalidate its review. **The mock copy is NOT a durable on-disk backup, atomic file transaction, crash recovery or proof of production safety.**
- `src/restore/firestore_gate7_readonly_model.mjs`: demo-only Firebase Admin SDK READ-ONLY transaction of Gate 6 account head and **current** immutable snapshot. It validates authenticated synthetic test UID match, expected revision, no economy hold, exact eight-domain metadata, schema, candidate structure and computed SHA-256 against stored head and snapshot hash. It refuses old revisions, missing or tampered snapshots and keeps prior history untouched. The returned `qaOnly` record is a **test fixture, not a real server authentication certificate**; no callable exports this.
- `tests/gate7_fixture.mjs`: fabricated account data only, no user save data.
- `tests/gate7_reversible_restore_sandbox.test.mjs`: 18 tests of exact real SaveManager registry, explicit consent, fail-closed security gates, identity change, stale CAS, local progress race, raw-token rejection, 10 fault injection points, backup retention, manual rollback and confirmation. They deliberately assert that tests never authorize real restore.
- `tests/gate7_firestore_emulator.test.mjs`: 8 suites using genuine Firestore emulator transactions and the existing Gate 6 QA writes; read-only current-head preflight, foreign UID, history conflicts, reconciliation holds, tamper, missing data, raw token rejection and synthetic device rollback without changing the database. **All Firestore writes in the new test suite are QA fixture seeding or synthetic corruption, never actual player operations.**
- Existing `.github/workflows/cloud-economy-gate5-qa.yml` runs the new syntax/Node suite and all Gate 5, 6 and 7 emulator suites in one localhost Firestore session. No new SDK dependency, project ID, endpoint, OAuth credential, service-account key, Firebase deploy or billing change.

## REQUIRED production gates (NOT PASSED here)

1. **Real disk transaction:** audited SaveManager-compatible atomic eight-domain write batch; durable pre-restore user backup, fully reversible crash/restart recovery and no overwriting local active-run data. Verify crash during any file rename/journal phase on real Android devices.
2. **Trust and economy:** unify Gate 5 global purchase ledger and Gate 6 full account revision under *one* authenticated, atomic server transaction; verified Play Developer API, spend reconciliation and refund/void handling are separate prerequisites. Reconcile legacy account ownership, obfuscated account IDs and token migration without logging/losing receipts.
3. **Freshness:** real Firebase Auth UID and enforced App Check; server transaction must recheck immutable snapshot revision, identity, economy hold and spend events at the restore decision boundary. Current QA `qaOnly` marker and digest are not server proof.
4. **UX:** explicit user choice, side-by-side local/cloud progression summary, no automatic first-login overwrite, conflict handling on two devices, no-loss offline flows, clear warning for irreversible actions, recovery after Android process death, and ability to cancel.
5. **Service security:** approved Blaze test project, least-privilege IAM, server-defined restore callable, reviewed Firestore Rules, fixed budget and monitoring, test purchase lifecycle and production release Play Integrity. **No live deployment has occurred.**
6. **Privacy:** reject local `iap:` token history before any transmission; design local-only irreversible migration with a server ledger acknowledgment and a testable rollback, rather than silently deleting a user's purchase history.
